# 消防系统运维：检测状态单向链路与历史数据对齐方案

本说明覆盖消防设施检测「提出 → 闭环」全链路的规则、依据与存量数据口径。所有业务判断集中在
`src/api/local-service.ts`，字段与状态登记在 `src/data/modules.ts`，存量迁移在
`src/data/migration.ts`，页面只渲染不判断。

## 1. 状态链路（单向，只能逐档前进）

```
待检测 ──提交检测──▶ 检测中 ──┬─ 判定正常 ─▶ 状态正常 ──归档──▶ 已归档
                              └─ 提出维修 ─▶ 需维修   ──归档──▶ 已归档
                                               │
                              检测结论自动回写隐患整改台账（挂出待整改）
                              隐患「提交验收」通过后回写维修完工并自动归档
```

- 跳转规则登记在 `modules.ts` 的 `transitions`：只允许相邻一档前进。
  - 跳档当场驳回，并在提示里写明缺哪一步，例如待检测直接归档会提示
    「缺『检测中』→『状态正常/需维修』」。
  - 回退（含从已归档回检测中）一律驳回；已归档是终态，任何动作都不给。
  - 新一轮检测只能对设施**新建检测单**（同一设施同一周期只允许一张进行中的单）。
- 「需维修 → 归档」必须先完成隐患整改：没有挂账、隐患单不存在、隐患未验收，分别给出
  对应缺步提示；隐患验收通过时由系统回写「维修完工日、检测结论」并自动归档，避免人工双录。
- 同一笔动作重复提交（当前状态已等于目标状态）只推进一次，第二次直接挡回。

## 2. 随状态落库的字段与回写

消防设施字段（`modules.ts firecontrol.fields`）：

设施编号、所属舱室、消防类型、探测器数量、联动测试日、责任人员、下次检测日、检测周期、
检测结论、维修完工日、关联隐患编号、扫描件编号、回填依据。

- 提交检测时四要素必录：设施编号、消防类型、探测器数量（>0）、下次检测日；缺项驳回并写明缺什么。
- 判定正常：检测结论写「检测合格」，以联动测试日（缺省取当日）为锚点滚出下一次检测日。
- 提出维修：检测结论回写隐患整改清单，新建一条 `待整改` 隐患（隐患部位、等级、措施、
  责任人、发现日、一个月整改期限、来源设施、来源检测结论），并把隐患编号挂回消防行；
  同一检测单只挂一次账。
- 隐患验收：回写维修完工日与复验结论，消防行自动归档，下一次检测日 = 完工日 + 周期。
- **待办条数一致**：`fireConsistency()` 实时核对「需维修且未闭环」的消防行数与隐患台账中
  对应「未验收」挂账数，页面顶部横幅展示，二者必须相等。回写与消防更新在同一保存动作内完成。

## 3. 同一设施 / 同一行重复与并发

- 同一设施存在未归档检测单时，登记入口按重复挡回（提示已有单号与当前状态）。
- 同一行（同一模块同一 id）并发两笔动作：`submitAction` 用在途锁（in-flight set）只放
  先到者拿锁落库，后到者返回「同一行有在途提交，按重复挡回，只认先落库的那一笔」。
- 每行带 `_updatedAt` 落库时间戳；纯前端 localStorage 无事务，用进程内锁模拟行级串行。

## 4. 存量数据与历史取值口径（依据与自拟口径）

迁移只在首次读到旧版数据时执行一次（localStorage 记录 `schema-version`），幂等可重跑。

1. **检测周期**：依据 GB 25201《建筑消防设施的维护管理》，建筑消防设施至少每年检测/维护
   一次，默认 **12 个月**；火灾自动报警系统按消防安全重点单位半年一次的实务口径取 **6 个月**。
   周期集中在 `migration.ts cycleMonthsFor`，可按类型扩展。
2. **存量设施按联动测试日回填**：`下次检测日 = 联动测试日 + 检测周期`。选联动测试日而非
   建账日，是因为它是最近一次可证实的检测行为锚点，能真实暴露漏检。
3. **早年没有下次检测日**：
   - 有联动测试日 → 按第 2 条；
   - 只有纸面单 → 按扫描件编号 `SCAN-YYYYMMDD-序号` 中的扫描日期建账，再 +周期；
     编号缺失的按同一编码规则补编号；
   - 连扫描日期都没有 → 以迁移上线日（`2026-10-06`）为锚点视为**已到期**，下次检测日即
     迁移日，并补扫描件编号。宁早报不漏报，下一轮实测后恢复正常滚动。
4. **历史取值有争议以归档件为准**：状态为「已归档」的行任何字段都不重算（`回填依据`
   标注「归档件为准」）；其余行的周期与下次检测日一律按上述口径统一重算，全库同一口径。
5. **隐患台账对齐**：存量「需维修」行若在隐患台账中没有对应未验收单，补挂一条
   `待整改`（整改状态标「存量回填」），隐患编号续现有 HAZA 流水号，并回写关联号。
6. **往期能耗单据按抄表周期搬入**：统计周期统一规范为月度 `YYYY-MM`（取抄表日期，空值取
   迁移日），即「往期单据按抄表周期搬入」的落地口径。

## 5. 导入明细与台账对账

`reconcileImport(key, csvText)`：导入文件必须包含首列业务编号与「当前状态」列；逐条比对
条数、状态与所有重叠字段，也不允许导入台账里没有的新行。任何不一致整批驳回并列出前 5 处
差异（格式 `设施 FIRE-xxxx 字段/状态不一致：导入「…」，台账「…」`），全部一致才提示对账通过。

## 6. 验证

`scripts/verify-firecontrol.ts`（`npx tsx scripts/verify-firecontrol.ts`）用内存 localStorage
覆盖 25 项规则：迁移各分支、归档件保留、跳档/回退驳回、重复动作与重复登记、并发只认一笔、
检测结论挂账与验收闭环回写、待办条数一致性、导入一致/篡改驳回。
