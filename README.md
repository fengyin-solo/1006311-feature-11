# 城市地下综合管廊运行维护管理平台

面向管廊主体台账、入廊管线登记、廊内环境监测、通风排水消防、结构沉降与渗漏处置、巡检检修与隐患整改、入廊作业审批和运维值班的一体化城市地下综合管廊运行维护管理工作台。

这是一个**纯前端**管理平台：Vue 3 + Vite + TypeScript，仓库里没有后端服务。业务数据由
`frontend/src/data/` 下的本地数据层提供：首次打开用示例数据播种，之后的登记、筛选与状态流转
结果都持久化在浏览器 `localStorage` 里，刷新或重开浏览器都还在。dev server 已关掉自动打开页面，
启动后按终端打印的地址手工打开。

## 目录结构

```text
.
├── frontend/                 Vue 3 + Vite + TypeScript 前端（唯一运行单元）
│   ├── src/views/            每个业务模块一个页面
│   ├── src/api/local-service.ts   本地数据服务：列表、筛选、动作流转、导出
│   ├── src/data/             模块元数据 / 示例数据 / localStorage 持久化
│   ├── src/stores/           会话与筛选状态
│   └── vite.config.ts        dev server 配置（open: false，无 /api 代理）
├── .gitignore
└── docker-compose.yml
```

## 启动

```bash
cd frontend
npm install
npm run dev
```

前端默认监听 `http://127.0.0.1:5173/`，dev server 不会自动打开浏览器，需要自己访问。

生产构建：

```bash
cd frontend
npm run build
```

## 约定

- 每个模块的页面在 `frontend/src/views/<模块>/index.vue`，页面只负责渲染，读写统一走
  `frontend/src/api/local-service.ts`。
- 字段、状态、动作与流转目标集中在 `frontend/src/data/modules.ts`；示例数据在
  `frontend/src/data/seed.ts`。
- 状态流转只允许在 `local-service.ts` 里改，页面组件不做业务判断。
- 想回到初始数据：清掉浏览器里 `urban-utility-tunnel:entries` 这一项，或调用 `resetModule(模块)`。

## 消防系统运维的单向链路

消防设施的状态收成一条单向链路：**待检测 → 检测中 → 状态正常/需维修 → 归档**，只能按
顺序往前，跳档当场驳回并在提示里写明缺哪一步；归档是终点，已归档的回不到检测中。领域规则
集中在 `frontend/src/data/firecontrol-flow.ts`（纯函数，可单测），流转接线在
`local-service.ts` 的 `runFireAction`。

- **随状态落库**：设施编号、消防类型、探测器数量、下次检测日、检测结论都写在台账行上，
  `消防状态` 列与当前状态保持一致。
- **检测结论回写**：判定「需维修」时在隐患整改清单挂上一条待整改（隐患编号
  `HAZA-<设施编号>`，整改期限为发现之日起 30 天，同一设施不重复挂单）；维修做完「归档」时
  该设施名下未验收的隐患同步验收回填。每次回写后隐患清单的待办标记按状态重算，待办条数
  与台账现状保持一致。
- **重复提交**：同一设施同一环节只推进一次；动作与往期单据都有提交流水
  （`localStorage` 里 `urban-utility-tunnel:firecontrol-submissions` / `-import-log`），
  同一行被两笔同时提交时只认先落的那一笔，另一笔按重复挡回。`resetModule('firecontrol')`
  会连同流水一起清空。
- **超期看管**：待检测、检测中且下次检测日已过的设施会被标成异常，在运营概览的异常量里
  能看出来，不会再「下次检测日到了还当成检测中」。

### 下次检测日的倒推口径（自定义依据）

- 检测周期取 **12 个月**，依据 GB 25201《建筑消防设施的维护管理》「建筑消防设施每年至少
  进行一次全面检测」。
- 下次检测日一律按「**联动测试日 + 12 个月**」重算（月末溢出钳到月末，如
  2024-02-29 → 2025-02-28），不直接采用历史单据上的旧值，保证全台账口径统一。
- 存量设施缺下次检测日的按联动测试日回填；联动测试日也缺失的无法倒推，标记异常待补录。
- 历史取值有争议时**以归档件为准**：同一设施编号下归档行的联动测试日、消防类型、探测器
  数量等取值优先，其余行按它统一重算。

### 往期单据搬入

- 往期单据按抄表周期搬入，早期只有纸面的按扫描件编号建账；往期单据都是已闭环的历史件，
  建账直接落「归档」。
- 去重键为「设施编号 + 来源单据」，重复单据只认先落的一笔。
- 台账已有归档件的，冲突字段以归档件为准；台账行未归档的只补空字段，冲突以台账现状为准。
- 搬入后统一走台账重算，保证导入的明细与台账现状一致。

页面上的「回填下次检测日」「搬入往期单据」两个按钮分别对应存量重算与示例批次搬入。
领域逻辑与集成链路各有断言脚本：`npm run test:flow`、`npm run test:service`。
